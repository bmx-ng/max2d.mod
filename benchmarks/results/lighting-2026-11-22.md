# Initial lighting diagnostics — 2026-11-22

[Metal CSV](lighting-metal-2026-11-22.csv), produced by `benchmarks/lighting.bmx`
in release mode on macOS 27.0.1 through SDL3 GPU/Metal. Each of 24 cases used
20 warmup frames and 60 measured frames, an 800×600 window and 256² shadow masks.
This was an exploratory desktop run, not an isolated hardware comparison.

## Work counts

The following values are per measured frame for 16 lights and filtered shadows:

| Receivers | Moving lights | Direct-light passes | Shadow rebuilds | Shadow cache hits |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 0 | 16 | 0 | 16 |
| 1 | 1 | 16 | 16 | 0 |
| 64 | 0 | 480 | 0 | 480 |
| 64 | 1 | 479.83 | 16 | 463.83 |

All cases had zero texture creations after warmup. Sixteen hard shadow masks
retained 4 MiB; sixteen filtered masks retained 12 MiB. Moving one light caused
all sixteen requested masks to rebuild, examining 256 caster/light combinations
per frame. Filtering added 32 blur passes per frame in that moving case.

These results identify two different costs: direct lighting scales with selected
intersecting receiver/light pairs, while mask construction is shared across
receivers. Finer shadow invalidation could avoid rebuilding unchanged lights
when only one light moves. Caster edits would still require identifying affected
lights, or conservative invalidation.

## Timing limits

CPU frame means clustered around 8.3 ms despite different work counts, consistent
with presentation pacing influencing the measurements. These numbers do not
establish a GPU performance limit or prove equal rendering cost. The benchmark
uses `Flip(0)` but does not force GPU completion. Repeat in a controlled desktop
session and use native GPU profiling before claiming a timing improvement.
