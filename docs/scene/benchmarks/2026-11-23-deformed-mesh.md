# General deformed-mesh lighting — 23 November 2026

Native lighting can now draw a non-overlapping mesh once per light group even
when every triangle has a different UV-to-geometry mapping. Application and scene
APIs are unchanged: enable light batching and use `DrawMesh` or a lit mesh node.
Providers opt into the new optional `DeformedMeshGeometry` capability.

## Rendering and fallback

The fragment shader reconstructs lighting position from framebuffer position and
a screen-to-lighting transform. UV gradients supply each triangle's normal-map
basis. Derivatives use the linear transform directly, avoiding subtraction of
large world-position values. Current object/parent transforms, camera, origin,
handle and virtual presentation are included. Degenerate fragment gradients use
a viewer-facing normal, as with the existing singular normal-transform fallback.

Full mesh bounds select point lights; selection is not based on the first
triangle's extrapolated image rectangle. The processor preflights every group
before drawing ambient or direct light. It can combine ambient with the first
group, use separate mapped ambient, or draw ambient only when no lights match.
A rejected group returns to the established section/triangle path before any
pixels are submitted. If support changes or drawing fails after submission starts,
the error propagates without a fallback redraw over partially rendered pixels.

Overlapping or degenerate geometry, singular drawing transforms, texture gradients
too small or ill-conditioned for reliable fragment precision (including atlas scale), unsupported
provider/material combinations and meshes above 512 triangles retain fallback.
The overlap check uses triangle bounds before separating-axis tests and retains
its result until geometry changes. Worst-case analysis remains quadratic within
the bound. No new vertex layout or public image-effect package ABI is required.
Native eight/sixteen-light packages now use 63/111 float4 slots and the existing
three textures. Shader sources and embedded assets are generated by BlitzMax.

## Same-build rendering comparison

`benchmarks/deformed_mesh.bmx` compares two renderer sessions using the same
native shaders: a provider advertising only individual triangles, and one also
advertising affine/deformed meshes. This is not a previous-version benchmark.
The receiver has 128 triangles covering a deformed 192×192 region in a 256×256
byte target, with 17 point lights, normal/specular shading and mapped emission.
Pixel comparisons precede each trial and allow at most two RGBA channel units.

Both Metal and OpenGL use sixteen-light capacity here. Triangle drawing needs
256 direct-light groups plus 128 mapped-ambient passes: **384 submissions**.
Whole-mesh drawing needs two direct-light groups plus one mapped-ambient pass:
**3 submissions**. Counts are asserted by the workload.

Median trial means, in microseconds, from three trials of 120 frames after eight
warm-up frames per trial:

| Backend | Geometry | Triangle CPU | Whole CPU | Triangle drained | Whole drained |
| --- | --- | ---: | ---: | ---: | ---: |
| Metal | Warm | 140.93 | 14.51 | 586.07 | 223.11 |
| Metal | Edited each frame | 139.30 | 26.92 | 578.54 | 239.62 |
| OpenGL | Warm | 1,891.81 | 169.56 | 6,262.18 | 3,190.70 |
| OpenGL | Edited each frame | 1,506.74 | 185.08 | 6,516.26 | 3,338.19 |

CPU time includes clear, draw and flush. Drained time additionally includes a
one-pixel synchronous readback per frame; it is not GPU-only time. Geometry edits
occur before the timed interval, but resulting cache validation/overlap work is
inside drawing. Timings include ordinary driver/queue/host variability and do not
establish game frame rates or performance on other machines. No allocation or
long-duration soak claim is made by this workload.

Raw runs: [Metal](2026-11-23-deformed-mesh-sdlgpu.csv),
[OpenGL](2026-11-23-deformed-mesh-gl.csv).

## Validation

The mesh suite now performs 366 checks across both affine-only and deformed-capable
sessions, compared with a triangle-only reference. It covers independent mappings,
normal/specular/emission maps, filtered shadows, projected patterns, winding,
reflection, overlap and tiny-UV precision fallback, direct edits, camera/parent transforms, virtual
resolution and letterboxing, clipping, singular drawing transforms, complete
receiver bounds, ambient-only drawing, provider rejection and failure recovery.
A provider rejecting only the final group verifies no partial whole-mesh drawing;
a provider changing support after the first submission verifies error propagation
and restoration of drawing state.

The existing 96-check mesh suite now expects one combined ambient pass per
eligible deformed mesh. Material-map and scene-lighting suites remain unchanged.
[Backend results](../validation/2026-11-23-deformed-mesh.csv) cover Metal/OpenGL on
macOS arm64 and D3D9/D3D11 as x64 applications on ARM64 Parallels. These Windows
runs establish correctness in that environment, not native Windows performance.
The CPU cache suite passes 12,615 checks, including retained-versus-fresh geometric
overlap results. The native shader generation test verifies source and embedded
asset reproducibility. SPIR-V was compiled but this report does not claim Vulkan
runtime validation.

The step remains deliberately bounded: self-overlap preserves painter order via
fallback, larger meshes retain per-triangle drawing, and native material sampling
still uses the existing packed specular and separate mapped-emission paths.
