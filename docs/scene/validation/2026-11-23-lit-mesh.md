# Direct lit mesh validation

`TMax2DLighting.DrawMesh` derives a UV-to-world mapping for each triangle and
submits it through the ordinary lighting shaders. `TLitMeshNode` adds scene
material dependency tracking, geometry bounds and explicit content invalidation.
No per-receiver capture is required. Grouped mesh lighting is not implemented;
existing sprite grouping remains available.

`tests/lighting_mesh.bmx` compares meshes against lit sprites with point and
directional illumination, normal/specular maps, emission, tint/alpha, camera
transforms, textured lights, shadows, trimmed artwork and unlit materials. A
uniform-texture reference checks illumination at interior pixels of deformed
triangles. Further checks cover drawing handles with an independent affine light
transform, early rejection of a singular UV triangle, state recovery after a
render-target feedback failure, scene cache reuse and material/geometry edits.
Pixel comparisons allow two channel units for rounding. The existing
`scene_lighting` suite additionally exercises the established sprite, material,
shadow and grouped-renderer paths.

[Results](2026-11-23-lit-mesh.csv) record completed runs. macOS builds use arm64;
Windows builds use x64 on Windows 11 ARM64 in Parallels. These are functional
checks, not throughput or allocation benchmarks. The worked example has a
three-frame smoke mode. No performance parity with sprite grouping is claimed.

From the SDK directory:

```sh
bin/bmk makeapp -r -ud max2d_sdlgpu -o /tmp/lighting_mesh mod/max2d.mod/tests/lighting_mesh.bmx
/tmp/lighting_mesh
bin/bmk makeapp -r -ud max2d_sdlgpu -o /tmp/scene_lit_mesh mod/max2d.mod/examples/scene_lit_mesh.bmx
/tmp/scene_lit_mesh --test
```

Use `max2d_gl` for OpenGL, or `max2d_d3d9` / `max2d_d3d11` with Windows paths
and `bin/bmk.exe`. The regression runner registers `lighting_mesh` on those four
shader-capable profiles. The SDL renderer does not support these lighting shaders.
See [usage and limits](../../lighting.md#direct-textured-mesh-receivers).
